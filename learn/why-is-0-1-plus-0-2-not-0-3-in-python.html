Why is 0.1 + 0.2 not equal to 0.3 in Python?

Computer ScienceCBSE Class 125 min readUpdated 15 November 2026
BM
Biswarup Mukherjee · Teaching Administrator, CBSEMock20 years of teaching · Reviewed by subject teachers · About us

Open Python and type 0.1 + 0.2. You expect 0.3. Python prints 0.30000000000000004, and 0.1 + 0.2 == 0.3 gives False. Python is not broken — this happens in almost every programming language, and the reason is a lovely piece of number theory.

The short answer

Computers store numbers in binary. Just as 1/3 never ends in decimal (0.333…), 1/10 never ends in binary. The computer must cut it off after a fixed number of bits, so 0.1 and 0.2 are stored as numbers a tiny bit away from their true values. Adding them makes the tiny errors visible.

Step 1: some fractions never end

In decimal (base 10), a fraction terminates only if its denominator has no prime factors other than 2 and 5. That is why 1/4 = 0.25 ends but 1/3 = 0.333… goes on forever. In binary (base 2), a fraction terminates only if its denominator is a power of 2. So 1/2 = 0.1₂ and 1/4 = 0.01₂ are exact, but 1/10 = 0.0001100110011…₂ repeats forever, because 10 = 2 × 5 contains the factor 5.

Step 2: the computer has to round

Python's float uses the IEEE-754 double-precision format, which keeps about 53 significant binary digits. The endless binary pattern for 0.1 is cut off and rounded, so what is stored is actually 0.1000000000000000055511151231257827… Similarly 0.2 is stored slightly above 0.2.

Step 3: the errors add up

When you add the two stored values, their tiny errors add too. The result is the double closest to 0.30000000000000004, which is not the same double that Python uses for 0.3. Python prints enough digits to tell them apart — hence the surprise.

How to compare decimals safely

import math

a = 0.1 + 0.2
print(a == 0.3)                 # False  — avoid == with floats
print(round(a, 2) == 0.3)       # True   — round to the precision you need
print(math.isclose(a, 0.3))     # True   — the recommended way

For money, where every paisa must be exact, use the decimal module (from decimal import Decimal) or store amounts as whole numbers of paise.

Why this matters for exams

  • Output-prediction questions sometimes include float arithmetic — remember that results like 0.1 + 0.2 do not print as 0.3.
  • When writing conditions on calculated decimal values, use round() rather than ==.
  • The underlying idea — binary representation and its limits — links to the number-system topics in Class 11.

Try it yourself

Which of these fractions can be stored exactly in binary: 1/2, 1/5, 3/8?

1/2 and 3/8 (denominators are powers of 2); 1/5 cannot.

What does print(round(0.1 + 0.2, 1)) display?

0.3

Write a condition that safely checks whether the float x equals 1.1.

math.isclose(x, 1.1) — or round(x, 2) == 1.1
