1.1 What is Artificial Intelligence?

Artificial Intelligence (AI) is the simulation of human intelligence processes by machines, especially computer systems. It enables machines to learn from experience, adjust to new inputs, and perform human-like tasks.

2.6 Data Acquisition — Collecting the Right Data

Data acquisition is the process of collecting, gathering, and importing raw data for an AI project. The quality of your AI model depends entirely on the quality and quantity of data collected — "Garbage In, Garbage Out."

Fig 2.5: Data Acquisition — techniques, categories, dataset types, and risks of poor data

💡 Why Authentic & Sufficient Data Matters Sufficient data means having ENOUGH examples so the AI can recognise patterns reliably — a face recognition AI trained on 100 photos will fail; trained on 1 million photos, it will excel.

Authentic data means real, accurate, unbiased data from genuine sources. If a hospital AI is trained only on data from wealthy urban patients, it will fail for rural patients with different dietary and environmental factors.

Genuine data sources include: Government databases (data.gov.in), open repositories (Kaggle, UCI Machine Learning Repository), research papers with published datasets, hospital records with consent, sensor networks, and verified social media APIs.

3.3 Normalisation — Why and How

AI algorithms (like KNN, Neural Networks) are distance-sensitive. If Age ranges from 0–100 but Income ranges from 0–1,000,000, the algorithm will unfairly favour Income. Normalisation rescales all features to the same range.

📐 Min-Max Normalisation Formula X_normalised = (X - X_min) / (X_max - X_min) Result: All values scaled between 0 and 1
📊 Worked Example — Normalise Student Heights Heights: [150, 160, 170, 180, 190] cm. X_min = 150, X_max = 190

• 150 → (150-150)/(190-150) = 0/40 = 0.00
• 160 → (160-150)/(190-150) = 10/40 = 0.25
• 170 → (170-150)/(190-150) = 20/40 = 0.50
• 180 → (180-150)/(190-150) = 30/40 = 0.75
• 190 → (190-150)/(190-150) = 40/40 = 1.00

Insight: The shortest student (150cm) gets 0, tallest (190cm) gets 1.
💡 Key Terms • EDA = Exploratory Data Analysis — understanding your data before modelling
• Missing values → fill with mean/median (imputation) or remove row
• Outlier → unusually extreme value (e.g. Age = 150)
• Normalisation → rescale features to 0–1 range
• Standardisation → rescale features to mean=0, std=1 (Z-score)

Chapter 5: Evaluation of AI Models

5.1 The Confusion Matrix — Your AI Report Card

After training an AI model, we must test how well it performs. The confusion matrix is a 2×2 table that shows where your AI got confused — predicting correctly, predicting wrong in different ways.

Fig 5.1: Confusion Matrix for Cancer AI (200 patients)

5.1b Understanding TP, FP, TN, FN — With Everyday Examples

The four cells of the confusion matrix each represent a different type of outcome. Understanding them deeply is the key to choosing the right metric for the right problem.

Fig 5.1b: TP, FP, TN, FN — explained with medical and spam examples for both types of outcomes

💡 The Memory Trick for TP/FP/TN/FN The FIRST word (True/False) tells you whether the AI was correct.
The SECOND word (Positive/Negative) tells you what the AI predicted.

• True Positive = AI said YES and it WAS yes → ✅ Good!
• True Negative = AI said NO and it WAS no → ✅ Good!
• False Positive = AI said YES but it was actually NO → ❌ False alarm!
• False Negative = AI said NO but it was actually YES → ❌ Missed case! (most dangerous in medical AI)

5.2 Four Evaluation Metrics — Calculated

📊 Full Worked Example — Cancer Detection AI TP = 85 (correctly detected cancer), FN = 15 (missed cancer!), FP = 20 (false alarm), TN = 80 (correctly said no cancer)

① Accuracy = (TP + TN) / Total = (85 + 80) / 200 = 165/200 = 82.5%
→ "82.5% of all predictions were correct"

② Precision = TP / (TP + FP) = 85 / (85 + 20) = 85/105 = 80.95%
→ "When AI said cancer, it was right 81% of the time"

③ Recall (Sensitivity) = TP / (TP + FN) = 85 / (85 + 15) = 85/100 = 85%
→ "AI found 85% of all actual cancer cases"

④ F1 Score = 2 × (Precision × Recall) / (Precision + Recall) = 2 × (0.8095 × 0.85) / (0.8095 + 0.85) = 82.92%
→ "Balanced measure combining precision and recall"

Fig 5.2: Precision vs Recall — the trade-off and when each matters

📐 Key Formulas Accuracy = (TP + TN) / (TP + TN + FP + FN) Precision = TP / (TP + FP) Recall = TP / (TP + FN) F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
💡 Remember • TP = Correct positive prediction (best!)
• TN = Correct negative prediction (best!)
• FP = False alarm — predicted YES but was NO (Type I error)
• FN = Missed case — predicted NO but was YES (Type II error) — most dangerous in medical AI!
• Accuracy paradox: If 99% of emails are ham, a model that predicts EVERYTHING as ham gets 99% accuracy but is useless!

3.2 Bayes' Theorem — The Core of AI Probability

📐 Bayes' Theorem P(A|B) = P(B|A) × P(A) / P(B) Where: P(A|B) = Probability of A given B has occurred
📊 Worked Example — Spam Filter A spam filter uses Bayes theorem. Given: 40% of emails are spam. "Lottery" appears in 80% of spam emails and only 5% of genuine emails. If an email contains "Lottery", what is P(Spam)?

• P(Spam) = 0.40, P(Not Spam) = 0.60
• P(Lottery|Spam) = 0.80, P(Lottery|Not Spam) = 0.05
• P(Lottery) = (0.80 × 0.40) + (0.05 × 0.60) = 0.32 + 0.03 = 0.35
• P(Spam|Lottery) = (0.80 × 0.40) / 0.35 = 0.32 / 0.35 = 91.4%

✅ A 91.4% chance the email is spam! The filter blocks it.

💡 Why Backpropagation is Critical
Without backpropagation, a neural network makes random predictions forever and never learns. Backprop is what makes deep learning possible — it's the algorithm that tells each individual weight in a network of millions of weights exactly how much it contributed to the error and by exactly how much it should change. Geoffrey Hinton (Nobel Prize 2024) pioneered its use in neural networks in the 1980s. Modern GPT-4 has 1.76 trillion parameters — all trained by backpropagation.

💡 Key Formulas • Perceptron: z = Σ(wᵢxᵢ) + b; output = f(z)
• Sigmoid: f(z) = 1/(1+e^(-z)) → output 0 to 1
• ReLU: f(z) = max(0, z)
• Forward Propagation: Input → compute z → apply f(z) → get prediction ŷ
• Backpropagation: Measure error (Loss) → compute gradients → update weights (w = w − η × ∂L/∂w)
• Error = Loss = how wrong AI is. Backprop minimises it over thousands of iterations
• GPU is essential for deep learning — parallel processing of millions of matrix operations
• CNN: Convolution → ReLU → MaxPool → Flatten → Dense → Softmax

Topic 6: Natural Language Processing (NLP)

NLP is the branch of AI that helps computers understand, interpret, and generate human language. From chatbots to translation apps — NLP is everywhere.

🤔 Why is Language Hard for Computers?
Humans understand "I saw the man with the telescope" instantly — but a computer struggles because the sentence has TWO meanings (did you use the telescope, or did the man have it?). Language is ambiguous, contextual, and cultural.

1. The 7-Step NLP Pipeline

Every NLP system processes text through a series of steps. Think of it like a factory conveyor belt — raw text enters one end, structured understanding comes out the other.

Fig 6.1 — The complete NLP pipeline: raw text is progressively cleaned, tagged, and converted to numbers for ML models to process.

2. Tokenisation — Splitting Text into Units

Word Tokenisation
"I love AI" → ["I", "love", "AI"] — splits on spaces
Sentence Tokenisation
"Hello. How are you?" → ["Hello.", "How are you?"]
Character Tokenisation
"AI" → ["A", "I"] — used in some deep learning models
Subword Tokenisation
"unhappiness" → ["un", "happi", "ness"] — used in BERT, GPT

3. Stop Words — The "Noise" Words

Stop words are common words that carry little meaning and are removed to reduce noise. Think of them as the "filler" words in language.

Fig 6.2 — Stop word removal reduces noise and helps models focus on meaningful content words.

4. Stemming vs Lemmatisation

Fig 6.3 — Stemming chops word endings; lemmatisation looks up the true root form. Lemmatisation is more accurate but computationally expensive.

5. TF-IDF — How Important Is a Word?

TF-IDF (Term Frequency–Inverse Document Frequency) measures how important a word is to a specific document compared to all documents.

TF-IDF Formula
TF(word) = (count of word in doc) ÷ (total words in doc)
IDF(word) = log(total docs ÷ docs containing word)
TF-IDF = TF × IDF

Fig 6.4 — TF-IDF rewards words that appear frequently in one document but rarely across all documents, identifying truly distinctive terms.

6. Word Embeddings — Words as Vectors

Word2Vec converts words to numerical vectors so that similar words cluster together in a mathematical space. The famous example: King − Man + Woman = Queen

Fig 6.5 — In Word2Vec space, "King" and "Queen" are close (both royalty) but separated along the gender dimension. Words with similar meanings cluster together.

7. Transformers — The Power Behind ChatGPT

Transformers revolutionised NLP with self-attention — the ability to consider every word's relationship to every other word simultaneously.

Fig 6.6 — Transformers use self-attention to understand which words relate to each other. "it" in a sentence about a tired cat correctly refers to the cat, not the mat.

8. Real-World NLP Applications

🎭 Sentiment Analysis
Amazon reviews: "Amazing product!" → POSITIVE (0.94). Used in brand monitoring and customer feedback.
🌍 Machine Translation
Google Translate: Hindi → English → French using seq2seq transformer models.
🤖 Chatbots & Virtual Assistants
Siri, Alexa, Google Assistant use NLU (understanding) + NLG (generation).
📋 Text Summarisation
Converting a 10-page report into a 5-sentence summary automatically.
🔍 Search Engines
Google uses BERT to understand search intent beyond exact keyword matching.
📧 Spam Detection
Gmail classifies millions of emails as spam/not-spam using NLP + ML.

Topic 7: Model Evaluation & Improvement

Building an AI model is only half the job. Knowing how well it works — and why it fails — is equally important. This topic teaches you to measure, diagnose, and improve ML models.

🎯 Why Evaluation Matters
A model that is 99% accurate sounds impressive — until you learn it's diagnosing cancer. If it misses 1% of positive cases, those are real patients who go untreated. Choosing the right metric is as important as building the model itself.

1. The Confusion Matrix — Visualising Predictions

A confusion matrix is a table that shows how many predictions were correct vs incorrect for each class. It is the foundation of classification evaluation.

Fig 7.1 — Confusion matrix for a COVID test model. The 10 false negatives (missed COVID cases) are more serious than the 15 false positives (healthy patients incorrectly flagged).

2. Evaluation Metrics — Precision, Recall, F1

Core Metrics (from confusion matrix above)
Accuracy = (TP + TN) / Total = (80+95)/200 = 87.5%
Precision = TP / (TP + FP) = 80/(80+15) = 84.2% — "Of all COVID+ predictions, how many were right?"
Recall (Sensitivity) = TP / (TP + FN) = 80/(80+10) = 88.9% — "Of all real COVID+ cases, how many did we catch?"
F1-Score = 2 × (Precision × Recall) / (Precision + Recall) = 86.5%

Fig 7.2 — The choice between precision and recall depends on which type of error is more costly in the real-world context.

3. The Precision–Recall Trade-off

Fig 7.3 — The precision-recall trade-off: increasing one typically decreases the other. F1-score finds the optimal balance point.

4. Overfitting vs Underfitting

Fig 7.4 — Underfitting models are too simple; overfitting models memorise training data but fail on new data. The goal is the right fit in the middle.

5. K-Fold Cross Validation

Instead of using a single train-test split, K-Fold uses the data K times, rotating which portion is used for testing each time. This gives a more reliable performance estimate.

Fig 7.5 — In 5-Fold Cross Validation, each of the 5 equal portions takes a turn as the test set. The final accuracy is the average of all 5 test scores — more reliable than a single split.

6. How to Improve a Model

Fig 7.6 — Six strategies to improve model performance, categorised by whether they address data quality, model architecture, or training procedure.

7. Learning Curves — Diagnosing Model Problems

Fig 7.7 — Learning curves plot accuracy vs training size. Underfitting: both curves low. Good fit: curves converge. Overfitting: large gap between train and test accuracy.

📋 Quick Reference: All Key Metrics
Accuracy = (TP+TN)/Total — Overall correctness; misleading with imbalanced data
Precision = TP/(TP+FP) — Quality of positive predictions; use when FP is costly
Recall = TP/(TP+FN) — Coverage of real positives; use when FN is dangerous
F1-Score = Harmonic mean of Precision & Recall — Best for imbalanced datasets
Confusion Matrix — Visual table of all prediction outcomes
Cross-Validation — Technique to get robust performance estimate

Topic 8: Computer Vision (CV)

Computer Vision teaches machines to see and interpret images and videos — enabling self-driving cars, face recognition, medical imaging, and much more.

🤔 How Do Computers "See"?
A digital image is simply a 2D grid of numbers. Each number (0–255) represents the brightness of one pixel. A 640×480 colour image = 640 × 480 × 3 = 921,600 numbers. Computer Vision is the art of finding patterns in these numbers.

1. Images as Numbers — Pixels and Matrices

Fig 8.1 — Every digital image is a matrix of numbers. Dark pixels have low values (near 0); bright pixels have high values (near 255). Colour images use three separate matrices.

2. Convolution — How CNNs Detect Features

A convolutional filter (kernel) slides across an image, multiplying its values with the pixels it covers and summing the result. Different filters detect different features — edges, curves, textures.

Fig 8.2 — A Sobel edge filter multiplies pixel values and sums them. Where dark and bright pixels are adjacent (an edge), the output is large; in flat regions, it is near zero.

3. CNN Architecture — Layer by Layer

Fig 8.3 — A full CNN pipeline: convolution detects features, pooling reduces dimensions, dense layers classify. Backpropagation trains the filters automatically.

4. Computer Vision Applications

Fig 8.4 — Computer Vision has transformed industries from healthcare to agriculture. The same CNN architecture underlies all these applications.

5. RGB Channels — How Colour Images Work

Fig 8.5: RGB = 3 stacked matrices. A colour image is a 3D tensor (H × W × 3) — this is the input to every CNN

6. Object Classification vs Detection vs Segmentation

Fig 8.6: Three levels of CV — Classification answers "what", Detection answers "what and where", Segmentation answers "exactly which pixels"

7. Computer Vision in Healthcare & Agriculture

Fig 8.7: Computer Vision in Healthcare and Agriculture — two sectors where CV is saving lives and transforming food security

🔑 Key CV Terms
Pixel — Smallest unit of a digital image | RGB — 3 channels (Red, Green, Blue) forming a 3D tensor (H × W × 3) | Convolution — Feature extraction operation using a sliding filter | Filter/Kernel — Small matrix that detects specific patterns | Feature Map — Output of a convolution layer showing where features were detected | MaxPooling — Downsampling by keeping the maximum value in each region

4. Deep Learning vs Traditional ML

Traditional ML

Feature engineering required by humans — expert must choose which features matter

Works well with small-medium datasets (hundreds to thousands of examples)

Interpretable — decision tree shows exactly why a decision was made

Algorithms: Decision Trees, SVM, k-NN, Naïve Bayes, Linear Regression

Fast to train on standard hardware (CPU)

Deep Learning

Automatic feature extraction — network learns what to look for from raw data

Needs large datasets (millions of examples) to outperform traditional ML

Black box — hard to explain why the network made a decision (XAI research)

Architectures: CNN, RNN, LSTM, Transformer, GAN, Diffusion

Requires GPU — training ResNet-50 takes hours even on powerful GPU
